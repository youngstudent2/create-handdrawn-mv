# 合成、特效与渲染

## 工具选择

先检查工程和运行时已有的工具，再按需要选择。需要研究新 API 或具体安装方法时查当前官方文档。

| 任务 | 可选方法 | 先验证什么 |
|---|---|---|
| 透视图层、网格摆动、复杂屏幕特效 | Python + ModernGL/EGL + GLSL | 能否建 context，shader 能否编译，读回方向是否正确 |
| 剪辑、音频裁切混合、最终编码 | FFmpeg / ffprobe | 滤镜和编码器可用，精确时长与音轨 |
| 简单拼贴或已有动画工程 | 用户现有编辑器或合成环境 | 素材与工程可编辑、批量渲染是否可用 |
| 素材总览、透明边界检查 | Pillow | alpha 正确，不能以此伪装生成新立绘 |

ModernGL 是可复用的方案，不是必选项。在无 GPU 环境，EGL 可能由 Mesa llvmpipe 软件执行；报告真实后端，不称为硬件 GPU 加速。试渲染后再估算时间。生成几十张图往往比合成更耗时，不能仅按渲染速度承诺总完成时间。

## 图层与效果顺序

推荐流程：背景 → 背景专用扭曲/万花筒/递归 → 后景道具 → 角色 → 受控前景 → 轻量整体调色/纸纹 → 镜头间转场。

若先把角色放进万花筒/递归画框再整体扭曲，新姿势可能变成不可读的装饰。需要“特效里有角色表演”时，把主体角色在强效果之后重绘为独立层。不要为了证明素材被调用而把角色藏在效果里。

按主体位置设置前景避让区，尤其保护眼睛、手势和道具。注意飞行丝带、花瓣、模糊和亮斑可能恰好遮住 A→B 的变化。检查关键变化前、中、后连续片段。

## A/B 的对齐与透明合成

1. A/B 应在生成阶段共享画布、镜头与主体支点。先检查尺寸；不要静默拉伸不同纵横比来“对齐”。
2. 在共享坐标中取两张 alpha 边界的联合框，并对两张应用同一个裁切框和同样外扩留白。各自紧贴轮廓裁切会造成切姿势时跳位。
3. 配准头部、躯干或动作支点；保留有意的动作变化，不把整个人物差异错误归一化。
4. 选择切换方式：节拍上的短切、纸片翻面或局部遮挡后换姿势。轮廓明显不同的手和身体默认每帧只显示一张；大幅肢体变化需要额外姿势。只有经运动预览确认不会形成双重轮廓时才考虑融合，时长极短也不保证安全。

以 A/B 的非预乘纹理采样值 `(Ca, aa)`、`(Cb, ab)`，混合比例 `t` 为例：

```glsl
float alpha = mix(a.a, b.a, t);
vec3 premul = mix(a.rgb * a.a, b.rgb * b.a, t);
vec4 outColor = vec4(premul, alpha); // 输出预乘颜色
```

使用该输出时，混合因子须为 `ONE, ONE_MINUS_SRC_ALPHA`。若整个引擎采用非预乘输出，应先用 `premul / max(alpha, epsilon)` 恢复颜色，再用 `SRC_ALPHA, ONE_MINUS_SRC_ALPHA`；切勿混用两种约定。额外不透明度应同时乘预乘 RGB 和 alpha。透明纹理边缘滤波仍可能引入颜色污染，需检查透明区颜色、边缘扩展与 mipmap。

上述公式只解决透明颜色混合，不保证不同姿势的动作成立。早期案例约 90 ms 的融合不能作为安全阈值；后续手部返修采用单姿势暴露消除了叠影。返修的定位与选择方法见 [人体、手部与转场返修](repair-anatomy-and-transitions.md)。

## 运动与转场

- 为角色、相机、前后景设不同运动曲线和深度，让相对运动建立空间。
- 网格摆动适合头发、裙摆或纸片的细微呼吸，不适合让手臂自动完成全新动作。
- 对站立角色保留支撑脚与地面的关系；不要把整个人物当作纸片旋转或缩放来模拟转身。区分整体相机取景与角色局部运动。
- 动作包含准备、发力、停留或回收，避免从头到尾匀速漂移。
- 转场可选纸条展开、同向甩镜、虹膜、波纹、旋涡、交叉变焦、短故障；根据相邻镜头的运动和情绪选择，不追求种类数量本身。
- 复用第三方 shader 时记录来源、版本/提交和许可证，保留必要的署名/许可文件。不因名字相同就假设参数和 API 相同。
- 用固定随机种子稳定粒子，方便复现和比较修改。缓存不变素材；不要为一个参数调整重新生成立绘。

## 编码与时间线

输出 H.264/AAC MP4 可作为通用交付选项；以用户指定规格为准。常见网页播放输出使用 `yuv420p` 与 faststart。宽高需与编码像素格式兼容，不改变用户要求的画幅以迁就示例。

明确目标时长、帧率和取整方式；固定帧率的视频应有与目标相符的帧数。把音轨明确裁切/补齐到目标长度并处理首尾，避免 `-shortest` 悄悄缩短影片。检查音画偏移、黑帧、首帧、末帧与尾音。

## 验收顺序

先验证能否渲染，再预览代表片段，然后完整渲染一次。检查最终编码文件，而非只看合成器预览。对已验证的问题做针对性修复，避免没有具体风险的重复全量测试。

导出素材使用记录，但诚实说明它的能力边界：绘制记录只能证明调用，不能证明角色没被后续图层覆盖。最后必须在成片中确认每一组姿势的可见性与动作可读性。
